# 视频AI剪辑 · 架构升级 v2（从"两步走"到"三环七段"）

> 文档目的：把 2026-02 打磨的那套"视频理解 → 创作"链路做一次**结构性**升级诊断与再设计，
> 并给出可直接落地的架构、契约与迁移路径。
> 读者：产品所有者、剪辑产品负责人、被派来实作的 AI Agent。
> 事实源：本仓 `bundles/video-edit/`（岗位/技能/围栏/契约/管线）+ `packages/video-studio/src/edit/`（参考实现）。

## 0. 结论摘要（五条结构性升级）

| # | 旧链路 | v2 升级 | 为什么这是"结构性"的 |
|---|---|---|---|
| 1 | 一次大 prompt 理解全片 | **确定性信号层 + 逐镜理解 + 叙事层**三段式 | 长视频的中后段字段坍缩、时间码漂移是"调用结构"决定的，不是提示词写得不够好 |
| 2 | 时间码秒级、模型自报 | **帧级时间码 + 信号层权威切点** | 剪辑的可用性下限由切点精度决定；3.2s 与 3.0s 在观感上不是同一件事 |
| 3 | 高光靠模型"觉得好" | **多信号加权 + 缺陷惩罚 + 三类关键帧** | 把"高光"从主观形容词变成可复算分数 + 可核对的证据帧 |
| 4 | 创作=填表（7 坑位 + 一堆硬规则） | **意图→发散→评审→技法库**四段，规则降级为默认美学基线 | 创作是艺术：规则该管事实（素材/授权/平台），不该替人决定怎么说故事 |
| 5 | 字段混用、无版本、无溯源 | **版本化 JSON 契约 + 证据链 + 只增不改** | 有了契约才能"单镜重跑、层增量返修、跨项目复用"，否则每次都从头再来 |

## 1. 旧链路全景（2026-02 备份）

```text
素材 ──▶ ①视频理解（VisionCut 单次大 prompt）
              └─▶ 结构化 JSON（shots[]：场景类型/画面/台词/技术参数/剪辑建议/内容价值）
        ②创意生成器（T01–T07 七个坑位）
        ③模板生成器（short_style_definer：题材/受众/语言/时长/字体）
        ④内容故事大纲（故事脉络 500–700 字 + 情感曲线 3–4 节点）
        ⑤制作剧本（场景 1..N：时间/素材来源/故事线/知识点/情绪/叙事描述/剪辑建议）
        ⑥剪辑脚本初稿（片段 original_timestamp + 时长 + focus）
        ⑦字幕版脚本（VMG 合并规则 + 字数带 + 无标点）
```

它当年的取舍是**正确**的：模型上下文与多模态能力有限，只能"一次看懂全片，然后逐段扩写"。
问题在于这套链路的**假设**已经过时：假设①理解可以一次完成；②时间码是给人看的；③创作靠规则收敛。

## 2. 九个结构性瓶颈（现象 → 根因 → 影响）

| # | 现象 | 根因 | 影响 |
|---|---|---|---|
| 1 | 30 分钟素材的解析结果中后段明显变空/复制 | 单次调用 + 长上下文衰减 | 剪辑师仍需人肉看片，AI 解析不可信 |
| 2 | 时间码与画面对不上（±1–3 秒） | 模型自报时间码，且只有 `mm:ss` | 切点落在半句话/眨眼帧上，成片"接不上" |
| 3 | 镜头切分与画面不符（把两个镜头写成一个） | 切点靠模型"看图猜"，没有信号层 | 高光区间跨镜，转场无从设计 |
| 4 | 台词文本存在错字/漏句 | 模型转写替代 ASR | 字幕与事实口径出错，需全量返工 |
| 5 | 高光片段"看起来都差不多" | 只有粗粒度 audio/visual 标签，没有量化信号 | 开头钩子选不出真正的高能片段 |
| 6 | 选封面帧靠"挑好看的" | 无关键帧概念与门槛 | 封面糊/压脸/信息被平台 UI 挡住 |
| 7 | 七个创意方案换汤不换药 | 坑位固定 + 情感标签覆盖要求 → 结构趋同 | 用户看完说"都差不多"，创意工作没价值 |
| 8 | 情绪曲线只是形容词 | 曲线没有时间轴与强度数值 | 剪辑无法按曲线排节奏，只能凭感觉 |
| 9 | 时间轴常出现重叠/空隙/时长对不上 | 主轨时间轴由模型心算 | 执行阶段反复返工；返修无法定位到段 |

## 3. 新架构 v2：三环七段

```text
┌────────────────────── 感知环（Perception，确定性优先） ──────────────────────┐
│ ① 信号层  probe        镜头边界 / 词级转写 / 节拍网格 / 音量包络 / 技术指标      │
│ ② 语义层  understand   逐镜多模态理解（人物/动作/实体/台词/情绪 + 证据帧）        │
│ ③ 高光层  highlight    多信号加权 + 缺陷惩罚 → 高光区间 + 三类关键帧             │
└──────────────────────────────────────────────────────────────────────────────┘
┌────────────────────── 索引环（Index，可检索可复用） ─────────────────────────┐
│ ④ 媒资层  index        标签 / 实体 / 可用性 / 复用建议 / 已用回链               │
└──────────────────────────────────────────────────────────────────────────────┘
┌────────────────────── 创作环（Creation，艺术与工程分离） ─────────────────────┐
│ ⑤ 意图与发散  intent + ideate     创作三问 → N 个差异化候选（不含自评）          │
│ ⑥ 结构与评审  structure           beat 表 / 情绪曲线 / 节奏图 / 素材映射 + 四视角评审 │
│ ⑦ 剪辑与交付  edit + caption + cutcheck + compose  帧级时间轴 / 字幕 / 质检 / 本地合成 │
└──────────────────────────────────────────────────────────────────────────────┘
                                   ↓ 交回既有后期链路
        调色 → 字幕版式 → 配音 → 配乐 → 封面 → 多风格交付 → 入库 → 返修
```

**设计原则**

1. **确定性优先**：能本地算的绝不问模型（切点、停顿、节拍、电平、时长）；模型只做语义与创作。
2. **分而治之**：逐镜调用，单镜可重跑、可版本化；一次失败的镜头不拖累全片。
3. **证据可核**：每条语义结论带证据帧与置信度；分数必须可复算。
4. **规则分层**：事实红线硬（素材/授权/平台/时长），美学默认值软（可覆盖、需留痕），创作自由区鼓励发散。
5. **只增不改**：结论/时间轴/交付都走版本链，返修是新版本，不是覆盖旧文件。

## 4. 五个升级点的详细设计

### 4.1 感知层：从"一次大 prompt"到"信号 + 语义 + 叙事"

**信号层（免费、可复现）**

```bash
pnpm edit:probe -- --input <素材> --out work/edit/<id>.analysis.json
```

| 通道 | 命令口径 | 产出 |
|---|---|---|
| 媒体规格 | `ffprobe -show_entries format=duration:stream=...` | 时长/帧率/画幅/音轨 |
| 镜头边界 | `-vf "select='gt(scene,0.3)',showinfo"` | 帧级切点列表 |
| 停顿 | `-af silencedetect=noise=-30dB:d=0.25` | 静音区间（切点与字幕用） |
| 响度包络 | `-af "astats=metadata=1:reset=1,ametadata=print:key=lavfi.astats.Overall.RMS_level"` | 峰值包络（高光/卡点用） |
| 峰值电平 | `-af volumedetect` | mean/max dB |

**语义层**：逐镜调用多模态模型，输入"抽帧 + 该镜词级转写 + 该镜技术指标"，输出 `shot_record`（带证据帧与置信度）。
**叙事层**：把镜头串成事件链（谁做了什么 → 结果），为结构设计提供"事实骨架"。

> 升级点：把"模型猜时间"换成"信号定时间"，把"一次看全片"换成"逐镜可重跑"。

### 4.2 高光与关键帧：从形容词到可复算分数

```
score = Σ wᵢ·signalᵢ − (0.5·抖动 + 0.6·失焦 + 0.4·遮挡 + 0.7·重复)
signals = 语音强调 / 音频能量 / 运动强度 / 表情 / 视觉显著性 / 语义价值 / 稀缺性
```

- 权重按内容 profile（知识/旅行/评测/剧情/口播）给默认值，覆盖需留痕；
- 三类关键帧：**情绪峰值帧**（封面/情绪点）、**动作峰值帧**（转场/卡点）、**构图最优帧**（封面底图）；
- 关键词：**可复算** —— 同一份信号必须算出同一个分数（`packages/video-studio/src/edit/highlight.ts`，含 24 项单测）。

### 4.3 创作层：把"规则"还给工程，把"表达"还给创作

| 旧做法 | v2 做法 |
|---|---|
| 7 个固定坑位必须输出 | N 个候选（默认 5–7），必须满足**至少 3 个维度真正不同** |
| 情感基调必须覆盖 5 种 | 情感不必"覆盖"，但每个候选要能说明"如果没有它，观众会少看到什么" |
| 字数/场景数/首场景时长硬约束 | 降级为默认美学基线；硬约束只保留事实类（素材/授权/平台/时长带） |
| 生成与打分在同一 prompt | **发散与评审分离**：四视角（叙事/情绪/平台/执行）独立打分 + 扣分理由 |
| 情绪曲线是文字 | beat 表 + 0–1 情绪强度曲线 + 节奏图（平均镜头时长/每分钟切点）+ 素材映射 |
| 没有技法库 | 转场语法速查（硬切优先/匹配剪辑/甩镜慎用）、声音设计（J-cut/L-cut/让位/留白/卡点） |

### 4.4 数据契约：版本化 + 溯源 + 只增不改

| 契约 | 文件 | 关键字段 |
|---|---|---|
| 素材理解 | `schemas/footage-analysis.schema.json` | 信号层 + 镜头层 + 高光/关键帧；每条带 `evidence`/`confidence` |
| 高光条目 | `schemas/highlight-pick.schema.json` | `signals`/`penalties`/`weights`/`recommendedUse` |
| 关键帧 | `schemas/keyframe-candidate.schema.json` | 三类 kind + 技术门槛 + 用途 |
| 剪辑时间轴 | `schemas/edit-timeline.schema.json` | 源轨/主轨分离、转场、声音、字幕位、校验块 |
| 创意与叙事 | `schemas/creative-set.schema.json` | 差异化矩阵 + 评审矩阵 + beat/曲线/节奏 |

统一口径：`schemaVersion`（契约版本）、时间码 `HH:MM:SS.mmm` + 帧号、素材 `sha256`、修订 `revision`/`prevRevision`。

### 4.5 执行层：从"模型心算"到"契约 + 本地合成"

```bash
pnpm edit:verify   -- --timeline <film>.timeline.json --report <film>.cut-report.json
pnpm edit:assemble -- --timeline <film>.timeline.json --out <film>.mp4
```

- 校验硬项：契约字段 / 溯源 / 源轨重叠 / 同源间隔 / 主轨连续 / 片段时长 / 枚举 / 总时长带；
- 咨询项：间隔未达理想值、片段偏长、总时长轻微偏离——提示但不阻断；
- 合成：逐段 `-ss/-to` 裁切 + 归一化（画幅/帧率/像素格式/音轨）+ concat 无损拼接 + 回执（含 sha256）；
- **替换掉的两步**：不再生成"视频提示词"，也不再渲染镜头；画面来自素材本身；
- **复用**：成片交回既有后期链路（调色/字幕/配音/配乐/封面/多风格交付），与生成片共用同一批工位。

## 5. 数据流转（端到端）

```text
上传素材
  └─ ingest（素材馆员）        → footage_asset（指纹/授权/用途/代 理）
      └─ probe（信号分析师）    → footage_probe（切点/转写/节拍/包络/指标）
          └─ understand（镜头理解师）→ shot_record[]（语义 + 证据帧 + 置信度）
              └─ highlight（高光猎手）→ highlight_pick[] + keyframe_candidate[]
                  └─ index（素材馆员） → media_index_entry（标签/实体/可用性/复用）
                      └─ intent（创意织工） → edit_intent
                          ├─ G-ED7 创作方向确认（制片 + 人审）
                          └─ ideate（创意织工） → creative_set（候选，不含自评）
                              └─ structure（叙事架构师） → story_plan + 四视角 review
                                  └─ edit-script（剪辑指导） → edit_script + edit_timeline（帧级）
                                      └─ caption（文案字幕师） → caption_script
                                          └─ cutcheck（剪辑质检师） → cut_report（硬项/咨询项）
                                              ├─ G-ED8 粗剪锁定（制片 + 人审）
                                              └─ compose（剪辑合成师） → final_video + 合成回执
                                                  └─ handoff（剪辑合成师） → edit_handoff → 既有后期
                                                      └─ archive（素材馆员） → 入库 + 复用回链
                                                          └─ revise（制片） → 层增量重合成
```

## 6. 与既有两条生成管线的分工

| 环节 | narrative-film / marketing-film（生成片） | edit-film（剪辑片，本架构） |
|---|---|---|
| 内容来源 | 剧本 + 提示词 + 渲染 | 真实/既有素材 + 理解 + 重组 |
| 提示词生成 | **必需** | **不需要**（改为镜头理解 + 剪辑脚本） |
| 渲染 | **必需**（Seedance 等） | **不需要**（本地裁切/拼接） |
| 定妆照/角色一致性 | 必需 | 不需要（素材里是谁就是谁） |
| 后期（调色/字幕/配音/配乐/封面/交付/返修） | 共用 | **共用**（同一批工位与同一份交付纪律） |
| 花费结构 | 渲染是原材料费（贵） | 模型费只在理解与创作；合成是本地算力（免费、可重跑） |

## 7. 边界（本架构不做什么）

1. **不生成画面**：剪辑管线不调用视频生成模型；需要新画面时明确走生成管线（并单独授权）。
2. **不替代人审**：创作方向（G-ED7）与粗剪锁定（G-ED8）必须人确认。
3. **不做审美硬闸**：越轴/景别/光线/音量只做咨询项（硬闸只保留事实类）。
4. **不自研模型**：多模态理解与创意调用现有模型路由（`model-policy.yml`），不训练自有模型。
5. **不做版权判定**：授权状态以素材提供方声明为准，系统只做"未声明即不入片"的 fail-closed。

## 8. 迁移路径（从旧链路到 v2）

| 步骤 | 动作 | 验收 |
|---|---|---|
| M1 | 用 `edit:probe` 跑通 3–5 条真实素材 | 镜头数与人工核对误差 ≤5%；停顿检出与听感一致 |
| M2 | 接语义层（逐镜），产出 `shot_record` | 抽 20 镜人工核对字段准确率 ≥90%，无幻觉实体 |
| M3 | 接高光打分，人工核对 Top-10 高光 | 人工认可率 ≥70%；关键帧三类的可用率 ≥60% |
| M4 | 创意与结构：7 坑位 → N 候选 + 四视角评审 | 候选两两"至少 3 维不同"检查 100% 通过 |
| M5 | 时间轴契约 + 本地合成 | 硬项校验 100% 通过；成片时长偏差 ≤5% |
| M6 | 复用既有后期链路出一支完整交付包 | 交付清单/旁挂字幕/封面/多风格变体齐备 |

## 9. 验收指标（怎么判断升级真的有效）

| 维度 | 旧链路基线 | v2 目标 |
|---|---|---|
| 切点精度 | 秒级、模型自报 | 帧级、信号层权威（±1 帧） |
| 解析可信度 | 中后段字段坍缩 | 逐镜解析，单镜可重跑；幻觉率 ≈0（无证据不落库） |
| 高光可用率 | 主观挑选 | 人工认可率 ≥70%（Top-10） |
| 创意区分度 | 7 个方案结构趋同 | 两两 ≥3 维不同（机器校验） |
| 时间轴返工 | 重叠/空隙频发 | 硬项校验一次通过率 ≥95% |
| 成本 | 模型逐帧/整片 | 信号层免费 + 理解批量谷时 + 合成本地 |

## 10. 已知未完成（诚实清单）

1. **逐镜技术指标**（清晰度/稳定性/噪声/色温）尚未在参考实现中计算，`technical.perShot` 如实返回 `null`；
   需要通过抽帧图像分析补齐（本地 CV 或轻量模型）。
2. **LUFS 未测**：`asset.audio.integratedLufs` 保持 `null`，只用 `volumedetect` 的 mean/max 作为参考（不冒充 R128）。
3. **节拍检测**：`music.bpm/beatGrid` 目前需要外部 BPM 检测器（本地库已有 `library-bpm` 能力，尚未接线到 probe）。
4. **UI 接线**：`ui/cases.json` 已声明剪辑台页面状态，三端页面尚未新增路由（当前版本以管线与契约为主）。
5. **合成转场**：已实现逐切滤镜链（T-2026-1011-0003）——`edit:post --transitions declared|auto` 把时间轴里的
   `transitionIn` 计划渲染成 FFmpeg `xfade`（46+ 种命名转场 + custom 缓动），硬切处走样点级拼接（不做"1 帧幽灵过渡"），
   每刀产出回执并机检黑屏/窗口/时长；默认仍是全片硬切（产品所有者 2026-10-10 口径）。口径与实测见
   [`video-edit-transitions.md`](video-edit-transitions.md)。
