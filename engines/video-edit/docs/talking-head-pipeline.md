# AI 口播精剪管线（edit-talk v1）· 设计与纪律

> 事实源：本仓 `bundles/video-edit/pipelines/edit-talk.yml`（管线）、`presets/talk-*.yml`（岗位）、
> `skills/talk-*/SKILL.md`（技能）、`fences/talk-edit-baseline.yml`（围栏）、
> `packages/video-studio/src/edit/talk.ts`（内核）与 `scripts/tools/edit-talk-*.mts`（执行器）。
> 本文回答三个问题：**口播为什么不能照搬通用剪辑**、**ASR 与情绪这两根主轴怎么落地**、
> **"活人感"如何变成可执行的指标而不是口号**。

## 0. 一句话定位

口播（怼脸随手拍、想到哪儿说到哪儿）的目标不是"剪得干净"，而是**在保留真人质地的前提下，
把信息与情绪剪出最好的那一条（或那几条）片子**。

与 `edit-film` 的根本差异：`edit-film` 的主要矛盾是"从多素材里选与重组"；
口播的主要矛盾是**同一条长镜头内的逐句留删**——留什么、删什么、留多长停顿、情绪怎么走。

两条管线共享：素材入库、确定性信号层、本地合成、以及**同一套后期交付**（调色 / 字幕版式 /
配音 / 配乐 / 封面 / 多风格变体 / 交付清单 / 返修）。

## 1. 行业实践调研（本轮可核实的证据）

| 结论 | 证据 | 等级 |
|---|---|---|
| 词级时间戳不是 ASR 的默认能力，句级/片段级时间戳本身就易漂移 | WhisperX 论文摘要：长音频转写易漂移/幻觉/重复，且"对应每句话的时间戳容易不准，词级时间戳并非开箱即得"（[arXiv:2303.00747](https://arxiv.org/abs/2303.00747)） | A（原文核实） |
| 行业主流做法不是"把静音剪到零"，而是**留一点边距**让剪辑"感觉更自然" | auto-editor（开源自动剪辑工具，GitHub `WyattBlue/auto-editor`）README：`--margin` 默认 0.2s，"adds in some 'silent' sections to make the editing feel nicer" | A（仓库原文核实） |
| 文本化剪辑（改文字即改视频）是口播/播客类内容的成熟交互范式 | Descript 等工具的公开定位；本轮未能打开其官方帮助页正文（HTTP 308/403），细节**未核实** | C（二手/未核实） |
| 国内工具（剪映等）把"口播精剪"做成显式功能入口 | 剪映官网学习页本轮只取到标题（页面为前端渲染），细节**未核实** | C（未核实） |

**未核实但被行业广泛采用的实践**（本文按其工程价值采纳，并在实现里明确标注为"默认值、可覆盖"）：
同机位跳切用推近/切镜遮盖；口播字幕按语义与呼吸断句、不卡音乐拍点；前 2 秒留白；
知识点用弹幕/贴纸做第二信息层；轻 BGM 且必须给人声让位。

> 诚实声明：本节只把"能打开原文核实的"标为 A；其余标 C 并在实现中作为**可覆盖默认值**，
> 不作为硬闸。发现与平台最新规则冲突时，以平台规则为准并更新本文件。

## 2. 两根主轴：ASR 与情绪

### 2.1 ASR：不是"转个文字"，而是**唯一事实源**

口播里"字幕 = 他说的话"，所以逐字稿承担三件事：字幕文本、剪取决策的时间骨架、点睛层的内容来源。
一旦它被"顺手润色"或时间戳漂移，后面每一层都会错。

落地：

1. **词级时间戳**（精度如实标注；句级稿必须显式放行才能进精剪）——对应围栏 G-TK1 与执行器 `pnpm edit:talk-asr`；
2. **口语标记**：语气词（填充/语篇连接）、停顿（换气/思考/死停）、重复（卡壳/词组重复/修辞强调/整句重启）、
   口误自纠（错句 + 纠正后说法）；
3. **话题块**：按显式连接词与死停切块，供选段、多片拆分与章节条；
4. **不做书面化润色**：把口语改成书面语 = 篡改原话（G-TK1，阻断级）。

### 2.2 情绪：**唤起度本地算、效价只用标注通道**

情绪是口播的第二主轴。工程化的难点是"别用错误信号冒充情绪"：

| 维度 | 怎么来 | 说明 |
|---|---|---|
| 唤起度（arousal） | 本地声学：语速 0.45 + 句内能量 0.35 + 能量变化 0.2 | 可复算、零模型成本 |
| 效价（valence）与情绪词 | **仅标注通道**（模型/人工标签） | 没有通道写 `null`，禁止猜 |
| 笑声/叹气 | **仅标注通道** | 能量峰值 ≠ 笑声；把喊话当幽默会让成片又吵又尬 |
| 峰值分类 | 情绪峰值（声学）/ 金句峰值（数字与结论锚点）/ 笑点峰值（标注） | 三类用途不同：钩子、知识卡、节奏缓冲 |

**峰值保护窗口**：自纠 > 笑点 > 情绪峰值 > 修辞强调。窗口内的语气词与停顿默认保留——
那是真实情绪的组成部分，不是"杂质"。

## 3. 口播精剪决策树（摘要版）

完整阈值表见 [`skills/talk-cutting/SKILL.md`](../bundles/video-edit/skills/talk-cutting/SKILL.md)。核心八条：

| # | 对象 | 处置 | 阈值 |
|---|---|---|---|
| 1 | 短促语气词（<0.25s） | 保留（口语节奏） | — |
| 2 | 常规填充语气词 | 删除（不在保护窗内） | ≥0.25s |
| 3 | 语篇连接词（然后/其实/就是） | 默认保留（删了断气） | 可删性 <0.5 |
| 4 | 换气停顿 | 保留 | <0.65s |
| 5 | 思考停顿 / 死停 | 压缩到 0.5s / 0.4s | 0.65–1.2s / >1.2s |
| 6 | 卡壳（连续重复） | 只留最完整的一次 | ≥2 次 |
| 7 | 修辞性重复（一口气复述） | **保留全部**（强调） | 间隔 ≤0.5s |
| 8 | 口误自纠 | **错句 + 纠正都留**，只压缩中间死停 | 提示词命中 |

**多片拆分**：一条长口播聊了多件事时，按话题块列出拆分候选（各有钩子与落点），
由人选（G-TK4）——不把三件事硬塞进一条片子。

## 4. "活人感"怎么变成可执行的指标

产品口径（2026-10-11，产品所有者）：**追求完美会摧毁信任；人类的不完美才是人的独特魅力**。
把它变成可执行的四件事：

1. **人味配额（下限）**：语气词保留率 ≥0.20、停顿保留率 ≥0.15（默认值，可覆盖）。
   跌破即**拒绝出片**，除非人审显式放行（G-TK6）——"更顺"不是理由，"人还在"才是底线。
2. **下限补偿**：跌破时按可删性从低到高恢复语气词、恢复句间停顿，并把这些动作写回台账。
3. **平滑风险指标**：语气词删除率 0.4 + 停顿删除率 0.3 + 语速平铺 0.2 + 跳切无遮盖 0.1；
   ≥0.70 触发告警——它是"这条片子像不像 AI 念稿"的量化代理。
4. **保留清单进保护窗口**：笑声、叹气、自问自答、口误自纠、修辞性重复一律先保后删。

## 5. 后期定制（与通用剪辑共用链路，但口径不同）

| 环节 | 通用剪辑 | 口播口径 |
|---|---|---|
| 字幕 | ≥2s 必上、字数带 `ceil(时长×2)–floor(时长×2.5)` | **跟着说话出字**（段多短都出）；一屏 ≤2 行、≤24 字；逐字等于 ASR 稿；不卡 BGM 拍点 |
| 声音 | 原声优先、BGM 让位 | 保留现场原声质地（呼吸/房间感）；**轻度 BGM**（默认 -24dB 量级）且不按拍点切 |
| 调色 | 按题材 LUT | 保留肤色与皮肤质感，不做"美颜式"过度处理（过度美化同样伤信任） |
| 点睛 | 弹幕轨（通用） | 知识点弹幕 / 贴纸卡 / 章节条：≤6 条/分钟、前 2 秒留白、避开字幕带与人脸区、文案逐字来自逐字稿 |
| 跳切 | 硬切优先 | 同机位跳切必须遮盖：相邻段推近 1.0↔1.12 交替（或切镜），否则观众会看到"跳帧" |
| 封面 | 平台规格 + 钩子公式 | 优先"情绪峰值帧 / 金句"；标题与副标题不重复、不写稿里没有的数字 |

## 7. 执行器与命令

```bash
# ① 逐字稿（三通道：导入稿 / 本机词级 ASR / 本机引擎 HTTP）
pnpm edit:talk-asr      -- --input <口播素材> --out outputs/edit/talk/<id>.transcript.json
#    导入已有稿：--transcript 校对稿.json|字幕.srt|字幕.vtt

# ② 情绪与活人感（本地声学 + 可选标注通道）
pnpm edit:talk-emotion  -- --transcript <…>.transcript.json --out <…>.emotion.json \
                          [--analysis <edit:probe 产物>] [--labels <标注.json>]

# ③ 逐句剪取决策 + 时间轴 + 逐字字幕 + 口播质检（一次产五件）
pnpm edit:talk-cut      -- --transcript <…>.transcript.json --emotion <…>.emotion.json \
                          --out-dir outputs/edit/talk/<filmId> [--target 60] [--punch-in alternate]

# ④ 点睛层（知识点弹幕 / 贴纸卡 / 章节条）
pnpm edit:talk-annotate -- --transcript <…> --cut <talk-cut-list.json> --timeline <talk.timeline.json> \
                          --out-dir <交付目录>

# ⑤ 既有工具链继续用：校验 / 合成 / 字幕门禁（口播口径）/ 弹幕渲染 / 后期交付
pnpm edit:verify   -- --timeline <…> --analysis <…> --report <…>
pnpm edit:assemble -- --timeline <…> --out <…>.mp4 --width 1920 --height 1080
pnpm edit:subtitle -- --talk --timeline <…> --caption <…> --transcript <…> --out <…>.srt
pnpm edit:danmaku  -- --input <…>.mp4 --items <danmaku.json> --out <…>-danmaku.mp4
pnpm edit:post     -- --timeline <…> --out-dir <交付目录> --subtitle <…>.srt
```

| 指标 | 口径 | 目标 |
|---|---|---|

| 删除端点合规率 | 落在词边界/停顿上的删除端点比例 | 100%（硬项） |
| 残句率 | 保留 <25% 的句子比例 | 0（硬项） |
| 人味下限 | 语气词保留率 / 停顿保留率 | ≥0.20 / ≥0.15（低于需人审放行） |
| 平滑风险 | 加权合成指标 | <0.70 |
| 跳切遮盖覆盖率 | 有景别变化的跳切边界比例 | ≥50%（低于挂起复核；实现默认 100%） |
| 情绪峰值可解释率 | 带证据的峰值比例 | 100% |
| 点睛密度 | 弹幕条目/分钟 | ≤6 |
| 成片时长偏差 | 与目标时长带偏差 | ≤5%（目标不明确时以决策台账时长为准） |

## 9. 边界与已知未完成（诚实清单）

1. **ASR 后端依赖本机环境**：本机未装 mlx-whisper / 无本机引擎时，只能走导入稿或引擎通道；
   三条通道都不可用时**失败关闭**（不产出空壳逐字稿）。
2. **说话人分离未实现**：多人素材只能整体转写；逐句说话人标注需要另行接入。
3. **笑声/叹气依赖标注通道**：本轮不做声学笑声检测（宁可缺失，不给假信号）。
4. **贴纸卡只出计划与安全区约束**：贴纸的最终渲染由后期贴纸工位执行（本轮不新增渲染引擎）。
5. **多片拆分只出候选与理由**：拆分执行（每条片子各出一版交付包）需要人选定后逐条走管线；
   批量拆片与账号级批处理未纳入本版。
6. **情绪曲线的"效价"**在无标注通道时为空：这不是缺陷，是纪律。
7. **行业调研的 C 级结论**（Descript/剪映的功能细节）本轮未打开官方页面正文核实，
   已在 §1 标注；如与平台最新规则冲突，以平台规则为准。

## 10. 与既有权重的冲突处理

- 通用剪辑的"同源片段间隔 ≥1s"在口播里**天然不成立**（同一条长镜头内密集跳切是体裁要求）。
  处理方式：时间轴显式声明 `sourceGapPolicy=single-take-talking-head`，该策略下间隔检查不再是硬闸，
  改由两条替代纪律管理：**源轨顺序单调递增**（不允许回跳复用，硬项）与**跳切遮盖覆盖率**（咨询项）。
- "审美口径不得写成硬闸"（T-2026-0930-0015）继续适用：口播的语速、平滑风险、跳切覆盖率都是咨询项；
  硬闸只保留事实类（逐字一致、端点对齐词边界、不剪残句、时间轴合法性）。
