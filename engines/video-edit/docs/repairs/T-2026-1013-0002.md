## 1. F8 · 独立音轨节目声 × 逐切转场计划（阻断级）

**现象**：带 `audioStems`（独立节目声）的片子 + 逐切转场计划（`perCut`，含硬切混合）时，
`muxAudioProgram` 以 `audio_stems_alignment_failed` 失败关闭（"独立节目轨与画面时间线相差超过 40ms"）。

**根因（三层）**：
1. `buildAudioStemTimeline` 只认整段 `fadeSec`，把**每一刀**都按同一个重叠折叠——逐切计划里每刀时长不同、
   还可能有硬切，节目声时间线与画面必然错位；
2. 复用缓存的校验与"重建 PCM 回放"同样只按 `mode/fadeSec` 重建，逐切计划下缓存永远对不上；
3. 画面是逐帧量化的（xfade 边界落在帧上），节目声理论总长与画面实测时长天然差几十毫秒，
   40ms 同步闸会把**量化噪声**当成不同步。

**修复**：
- `buildAudioStemTimeline({ shots, transitions, cuts, padToSeconds })`：新增逐刀回执口径
  （`cuts: [{toShotId, durationSeconds}]`；缺席的切点按硬切 0 处理，无 `cuts` 时才退回整段 `fadeSec`），
  并允许按**画面实测时长**给节目轨补尾部静音（`padToSeconds`，逐镜头样点不变，只在时间线里记录 `naturalSamples`）；
- `combineRole`：0 重叠的刀不再走 `acrossfade`（ns 必须 ≥1 样本），按 run 分组——run 内叠化、run 间 concat；
- `verifyAudioStemBundle`：按缓存里**已生效的逐刀重叠**回放时间线，回放渲染同样带 `cuts`/`padToSeconds`；
- `post-bridge`：母版节目声改到**拼接之后**生成，逐刀口径直接取自转场回执；变体与返修链路同样按各自回执对齐，
  并按画面实测时长补齐；节目声复用指纹把 `cuts` 一并纳入。

**验证**：
- `bundles/ai-video/connectors/post-bridge/audio-stems.test.mjs` 新增 2 例（逐刀时长各自生效 + 硬切不重叠；回执缺席时退回历史口径）；
- `delivery-integration.test.ts` 新增「独立音轨节目声 × 逐切转场计划」真实交付回归（修复前 fail-closed，修复后 `passed=true`）。

## 2. F5 · 弹幕进入交付形态（能力接线）

**现象**：弹幕能力只在 `subtitle-bridge` / `edit:danmaku` 独立工位存在，`edit:post` 的交付包里没有弹幕形态，
客户拿到的"完整成片"看不到弹幕。

**修复**：
- `edit:post --danmaku <条目.json>`（+ `--danmaku-lanes` / `--danmaku-opacity`）：在「烧字」形态（未烧字则用干净变体）上
  再烧一层弹幕，产出 `variants/<id>/<id>.burned.danmaku.mp4`，回执写进 `delivery-manifest.json#danmaku`；
- `edit:cover`：烧封封面时把弹幕形态一起叠成 `…danmaku.cover.mp4`，并把它列入 `publish` 推荐件（附弹幕口径说明）；
- `scripts/tools/lib/delivery-forms.mts`：弹幕形态命名与推荐件口径（`danmakuFormFile` / `recommendedDanmakuFile` / `DANMAKU_PUBLISH_NOTE`）。

**验证**：`scripts/tools/delivery-forms.test.ts` 覆盖命名与推荐件；真实渲染链路在客户片《带媳妇回山东老家》V5 交付中实测（4K / 16 条弹幕 / 检查项全过）。

## 3. F7 · 分段调色语义收敛（不再产出"与母版等价"的变体）

**现象（审计抽帧核对）**：`--segment-color` 产出的 `segmented-story` 变体与干净母版**逐帧一致**（8/8 抽样 sha256 相同）。

**根因**：分段调色作用在**共享片段层**（所有变体与母版都带），而 `segmented-story` 只是把变体层的统一 look 关掉——
它是"母版的副本"，不是第四种观感；同时其它变体还会在分段调色之上再叠一次自己的统一 look（双重调色）。

**修复（语义收敛，不造假变体）**：
- 分段调色明确为**片段级校正层**（交付形态共享，回执逐段记账）；
- `edit:post` 不再自动生成 `segmented-story` 变体；显式点名该变体会**报错**并给出替代路径：
  三风格变体 + `--segment-color`，或 `--color-map` 逐镜显式 profile/LUT/强度/校正。

## 4. F2 · 暖调故事版配方重定标 + 逐镜显式调色（`--color-map`）

**现象**：客户反馈"暖调故事版很多镜头太灰暗"。逐镜实测：山路段 YAVG 175 但动态范围仅 93、饱和 7.1（灰雾平光）；
溪水段 YAVG 97.6（偏暗）；日出段动态范围 76（灰蒙）。根因之一是 `warm-film` 满档的**提黑位**把灰雾镜头压得更平。

**修复**：
- `library/style-variants/warm-story.json`：`warm-film@0.75` → `high-contrast-social` 打底 + `look-warm-film.cube@0.5`
  （保暖调、把中间调对比/饱和拉回来）；
- `edit:post --color-map <json>`：**逐镜显式调色**（profile / LUT / intensity / corrections，走 color-bridge 口径：
  normalize/colorTemperature/colorBalance/curves/eq），只对列出的段落重编码，其余零行为变化，逐段回执记账。

**验证**：客户片 V5 用 `--color-map` 修 4 段（山路去灰雾、溪水提亮、群山/日出提对比保暖），4K 交付实测通过；
配方与实现均在回执里可核对。
