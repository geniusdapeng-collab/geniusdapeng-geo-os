# T-2026-1024-0008：营销提取输入合同与严格验证器同源

VID-1002 第四次预生产的真实 A1 输出给 `images` 添加了 `width` 和 `height`，触发 `MARKETING_PAYLOAD_INVALID`，未进入视频生成。原提示词只给出 `images: []` 示例，没有列出合法图片对象结构；严格验证器正确拒绝了多余字段。

当前阶段的完整 JSON Schema 直接由现有 Zod 输入验证器生成，随完整来源、原生采集计划一起发给提取模型，明确嵌套对象字段、类型、必填项和数量上限。选用同源合同，避免单独维护另一套手写字段表。既有 schema、原文绑定、独立支持审核、一次引用结构纠错及正式审批规则保持原行为。模型仍输出多余字段时原样保存并拒绝，不删字段或改写模型输出。

新提取档案标为 `workloom.marketing-extraction/v3`，复读时同时核对当前阶段的完整输入合同。已发布 v1 原文引用和 v2 片段引用保留原字节前缀与严格复读路径；版本降级、合同缺失、合同换阶段或合同放宽即拒绝。

独立测试还发现，严格 A1 允许省略图片的 `source`、`angle`，而实际 A5 装订要求两者非空。现仅在 `toJennyMarketingRaw` 的装订副本中，从本次核实页面的最终 URL 派生来源域名，未提供角度时标记 `unknown`；图片必须仍是当前阶段实际页面列出的地址。原始 payload、引文、独立评审与摘要不变，不把未知角度推断成某个视角。实际 HTML 页面图片的四种可选元数据组合均纳入 A1–A5 与最终事实复读测试。
