## 原因、选择和实际行为

[B] 原项目 `VID-1002` 的第三次前期 `RUN-4203894e` 在真实文字模型提取后被 `MARKETING_CITATION_INVALID` 拒绝。保存原文含“悬挂部分，新车采用 KYB 品牌组件”，模型写成“悬挂部分采用 KYB 品牌组件”。这属于改写，原严格拒绝正确；本任务不将该次失败改成通过，不覆盖其档案。

[A] 比较两个方案：继续要求模型重复抄写原文，改动较少，但仍可能漏字；让模型选择完整正文中确定编号的片段，由宿主从当前保存的原文装订，增加少量确定性处理和证据复读，但避免依赖模型逐字复制。采用后者，不使用模糊匹配或引文归一化。

[A] 每个来源先验证完整文本 SHA-256，再切成至多 640 个 UTF-16 码元的连续片段，优先在段落/句末结束，不拆代理对或 CRLF。片段连接后严格等于原文，不删除长正文或尾部限制。ID 指纹绑定来源 ID、完整正文摘要、起止位置和该段原字节。相同文本但不同来源不能互用 ID。

[A] 模型请求携带完整 `textFragments`，引用选择 `{pointer, sourceId, quoteId}`。宿主只从当前来源重新生成的片段表装订 `quote`，输出原事实验证器接受的格式。原始 `payload` 保持不变。伪造、跨来源、旧正文的 ID 或同时带 `quote` 与 `quoteId` 均拒绝。旧字面 `quote` 仍走逐字校验，改写仍拒绝。

[A] 提取档案使用 `workloom.marketing-extraction/v2`，保留完整原始请求、模型 `content`/`data`，另存 `citationBindings`（片段 ID、正文摘要、起止位置、引文摘要）。复读时重新装订并逐值比较；只更改状态或重算外层摘要不能通过。旧档案保留精确旧提示词前缀、完整来源和原严格验证，升级不使此前合法的 v1 提取失效。

[B] 独立审查发现重复文本时，原验证器的 `indexOf` 会取第一次出现，可能与选中的后一个片段位置不同。[A] 因此宿主装订时同时给出受控 `quoteStart`；验证器只接受该位置切片与引文逐字相等，位置不匹配不会回退到其他位置。无位置的旧 `quote` 继续取首次；归档事实复读重验已记录的准确位置。原 claim 内容标识保留，避免升级改变旧档案的 claim ID。

[A] 原来的引用结构纠错继续最多两次，第二次不能删改 `payload`；错误引文、错误 ID、模型失败、写盘失败或独立支持审核拒绝均不能借此绕过。原单次请求 90,000 字符上限保留，超过直接失败，不裁剪正文。片段存在仅证明引用确在保存正文中，主张是否被原文支持仍由独立完整语义审核决定，后续逐镜事实审核也保留。

三个场景：① 规格提取选择实际原文 ID，系统装订后交独立审核；② 来源正文或选中片段变化，旧 ID 失效并拒绝复用；③ 升级前的合法字面引文档案仍可复读，改写或伪造档案继续拒绝。P0 为完整分段、选择、装订、归档与复读；没有追加 P1/P2 功能。没有新增 API、数据表、第三方依赖、自动批准、社交发布或视频重做。
