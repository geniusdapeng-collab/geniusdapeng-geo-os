# 按需首尾快切：理解、决策、执行与成片复验

任务 T-2026-1015-0802；适用于视频剪辑仓的既有素材二次创作。使用者是剪辑导演、后期工位和给出素材及故事目标的创作者。

快切用于提前给出视觉信息、汇拢情绪或展示动作变化。完整台词、动作因果、可读的落版和请求时长优先于镜头密度。开头与结尾分别决定，自动模式可以选择首尾、只开头、只结尾或自然节奏，并保存选择与弃选理由。

## 三个实际场景

1. 旅行回忆：故事大纲要求快速呈现目的地，结尾保留人物一句完整话。素材理解提供多个无台词短区间，系统只做开头快切，正文与末句保持原速和顺序。
2. 产品或运动展示：开头展示用途，结尾在可读的最终定格前回收动作高光。可用素材充足且有时长余量时，系统两端选镜；音乐卡点必须来自最终使用的音乐文件，不能仅凭 BPM 标签。
3. 采访、教学或克制的故事：若首尾靠台词或完整动作承接，或没有可靠的理解证据，系统保留自然节奏并解释原因。明确强制快切而条件不足时给出可修正的错误，不切碎句子、不擅自延长。

## 方案与选择

| 方案 | 优点 | 成本与风险 | 适用前提 |
|---|---|---|---|
| 只在提示词和技能里写“首尾快切” | 接入少 | 无确定选镜、时间码、音乐和成片一致性证明；容易只在中间出现短镜头 | 仅用于创意建议 |
| 在现有时间轴上增加可复算的节奏导演与执行回执（采用） | 重用裁切/混音/后期；每一刀绑定源区间，字幕和转场使用同一时钟 | 需增加理解字段、时长预留、音乐测量和最终检查 | 已有故事草案与真实素材理解 |

## 执行流程

素材入库与理解 → 故事大纲/制作剧本声明每端目的、能量与保留内容 → 草稿时间轴 → `edit:rhythm` 决策选镜 → 最终时间轴 → 字幕 → 剪辑验证 → 正式后期 → 实际分区/音乐/字幕/源文件复验。

`edit:auto` 在正文排片前预留安全短镜与时长，含必须保留动作的镜头留给正文。正文粗排超过预算时，只在完整台词和动作边界之外收尾，不能满足时明确失败。排片后、字幕前调用相同导演；仅有 probe 而没有语义理解时保守选择自然节奏。正式后期消费已编译时间轴，不在字幕完成后插入新镜头。

## P0、P1、P2

- P0（本次）：四种决策及理由；自动从理解结果选取未使用区间；两端独立适用性；原速裁切；台词/动作的不可截断与必须保留两种约束；请求时长带；结尾停留；源散列绑定；可选实际音乐瞬态测量与时间映射；字幕时钟绑定；正式后期预检及真实输出复验。缺少任一项会让用户面对错误镜头、截断信息或计划与成片不一致。
- P1（后续）：用更多已授权成片建立体裁偏好与阈值校准。当前规则是透明可调的编辑默认值，不作审美评分。没有该项仍能可靠执行本次明确合同。
- P2（后续）：根据用户评审学习选镜偏好和多方案对比。没有该项不影响事实正确性与可追溯交付。

## 数据模型与接口

不新增数据库表；事实随项目文件及现有交付清单保存。素材理解新增 `shots[].editing.rhythm`（适用端、可靠安全区间、语音/动作已审标记、不可截断区间、必须保留区间、理由），并绑定 asset.sha256 和许可。故事输入为 `story.rhythm`：mode、opening/ending 的 purpose/energy/reason、durationBand、clipCount、clipSeconds、minLandingSeconds、beatSync 和可选 music。

`compileRhythmDirection({timeline, story, analyses, music})` 返回新的时间轴。`rhythmDirection` 保存所选模式、拒绝理由、输入散列、原正文编号、选镜事实、最终时钟、时长带和音乐绑定；`rhythmPlan` 继续服务既有逐片段实测。散列用于内容绑定，不是平台签名或人工批准。

CLI：`pnpm edit:rhythm -- --timeline draft.json --story story.json --analysis understood.json --out compiled.json`。`--analysis` 可重复；输出独占创建，失败保留诊断而不覆盖成功产物。`edit:subtitle` 输出串接时钟 SRT，侧车回执绑定新时间轴、SRT 当前字节和预期最终时间；后期统一做一次转场映射；`edit:post` 在裁切前拒绝陈旧字幕、节奏计划或输出参数。

主要错误码：`RHYTHM_DIRECTION_INPUT`（字段/范围非法）、`RHYTHM_DIRECTION_UNAVAILABLE`（强制模式缺少足够安全区间/时长/节拍）、`RHYTHM_DIRECTION_CHANGED`（编译后时间轴漂移）、`RHYTHM_PROTECTED_CONTENT`（保护区间被截断或丢失）、`RHYTHM_MUSIC_CHANGED`（最终音乐与测量字节或映射不符）、`RHYTHM_SUBTITLE_CHANGED`（字幕未基于当前时间轴）、`RHYTHM_OUTPUT_MISMATCH`（实际成片不满足合同）、`RHYTHM_OUTPUT_MUSIC_ALIAS`（输出或清理目录与曲库重叠）。

## 时钟、失败与容量

所有新增片段维持 1x，短镜头默认 0.4–1.2 秒、每端默认三段、落版默认至少 1.5 秒；可在约束范围内配置。已提交草稿的正文不删、不加速；自动粗排在形成草稿前按原目标时长和保护边界收尾。时长不足时自动缩减为单端或自然；强制模式明确失败。时长带保留用户原始请求，不能用已选正文时长覆盖。转场重叠从最终时钟扣除；快切内部及快切/正文边界使用硬切，冲突的声明不会被悄悄删除。

音乐可不用；显式指定的音乐在自然节奏和不要求卡点时也保留，禁用配乐优先。启用 beatSync 时先固定实际曲目与许可、选段、循环和入场，再测实际音频瞬态，按最终时钟选切点。没有可测瞬态则自动回退自然，强制请求失败。测量不是对音乐拍子的审美判断；最终回执同时核对实际保留音乐轨、混音和可测落点。发布复验重新核对原素材、原音乐、音乐床、逐刀执行回执以及当前全部交付形态的字节。

计算假设：单个本地项目、最多 1,000 个素材区间、成片最长 30 分钟；不增加网络或付费模型调用。输入、源片与成功输出只读；新文件写入失败、解码超时、资源不足均显式失败。并发同一输出使用独占创建阻止覆盖。新版本使用新输出目录；回滚撤销本任务提交即可回到旧自然剪辑入口。

输出不能与显式曲库、默认所有者曲库、环境指定曲库或随包曲库重叠，包括父目录、子目录和物理路径别名；此检查在任何输出写入及 `--clean` 前执行。非法请求值（例如 `mode:null`、字符串形式的 `beatSync` 或空的镜头数量）同样在生成媒体前拒绝。

`edit:auto` 要求独立且为空的输出目录，不允许素材、故事文件或理解文件位于该目录内。`edit:rhythm` 同样保护时间轴及 `.assets` 目录；两者用独占尝试标记阻止并发任务写入同一版本。失败目录保留，重试应换新目录。动作起止必须使用源片时钟，并与所属镜头相交；跨镜头的完整动作仍受保护。

## 验证与边界

纯函数覆盖自动四种选择、强制/禁止、空/最大/非法输入、保护区间、重复源、时长带、转场和时钟漂移。CLI 与真实 FFmpeg 测试覆盖源散列、故障、音乐、字幕以及开头/结尾实际切点；实际裁片到归一化输入、逐刀执行回执和母版对应帧构成执行证据，画面变化量只作咨询；独立角色在干净提交运行 MCD 验收。固定完整测试输出与实际提交，云端原仓 CI 通过后普通合并并回读两个 main。

本次不改生成视频管线，不重新生成成功原片，不自动请求 ASR/TTS/付费模型，不保证观众偏好或“大片感”评分。全 276 项生产 RDAS 与真实商业效果不由本机媒体夹具代签。FFmpeg 原速时间裁切/时间戳重置和本地解码参照[官方滤镜文档](https://ffmpeg.org/ffmpeg-filters.html#atrim)；实际支持以运行日志为准。

路径包含判断使用系统分隔符，并通过 Node 的 POSIX/Win32 路径实现检查同级、父级、跨盘及 UNC 反例，依据 [Node Path 官方文档](https://nodejs.org/api/path.html#windows-vs-posix)。本机真实媒体验证运行于 macOS；这不代表 Windows 实机媒体验收。后期旧接口的冒号分隔根目录列表保持原合同，其 Windows 盘符兼容性另需专项验证。
