# 正式交付包与多风格变体

## 一、交付目标与默认政策

让用户能使用完整文件、理解版本和继续返修。成功渲染镜头只读复用，后期改变颜色、音乐、文字或封面不重新付费生成。真实供应商 failed、来源不符、字节被改、权限不符和实际执行失败必须停止。

不重新评分成功源片的身份、服装、动作、嘴型、台词和艺术画质/声音品质，不调用品质模型、ASR、补 TTS 或人工 canary；当前后期的完整解码、实际规格、加工链和响度/真峰值仍按技术验收执行。普通 UHD 请求由本地编码器输出目标画布；明确需要增强时使用单独的增强工位及其真实来源回执，post 交付不会替用户启动模型。

## 二、前置校验

1. 登记的镜号唯一，供应商真实终态成功、taskId/assetId 与当前文件绑定；历史品质失败保持原样，追加独立接受回执。
2. 原始输入、源文件与工程中当前 SHA-256 一致；缺血缘或外部替换不得假称复用。
3. 租户、工作区、项目、许可、字体和曲目范围有效；本地完成不自动发布外部平台。
4. 请求的变体、字幕模式、目标画布、封面与输出目录明确；缺项按合理默认计划，不能依赖旧固定 30 秒 / 6 镜头模板。

## 三、产物与工程表

| 产物 | 工位路径口径 | 用途 / 必须记录 |
|---|---|---|
| 干净母版 | master/master-clean.mp4 | 本地组合地基、SHA-256、实际宽高和时长 |
| 旁挂字幕 | subtitles/ 下 SRT / ASS / VTT | 字体与 cue 同源，文件字节与时间轴回执 |
| 变体成片 | variants/<变体>/ 下 MP4 | 实际配方、音频策略、滤镜和文件哈希 |
| 软字幕轨版 | 变体的 softsub.mp4 | 可开关字幕，完整视频/原音频编码包对账 |
| 硬字幕副本 | 明确请求时的 burned.mp4 | 新文件，干净母版保留 |
| 封面 | 变体 cover.png | 明确标题、字体、当前图像画布与哈希 |
| 文案包 | copy.md / copy.json | 标题、正文、话题与 CTA；真实规则处理结果 |
| 音频回执 | audio.json | 曲目来源、许可、原声策略与实际操作参数 |
| 交付清单 | delivery-manifest.json | 每个真实产物、版本、SHA-256、品质未测字段 |
| 工程文件 | film-project.json | 原镜头和各后期层血缘，返修输入 |
| 人看说明 | delivery-report.md | 文件用途、配方差异与返修入口 |

真实全链 CLI 也有自己的项目文件命名。按调用入口的 manifest 查产物，不能把此工位路径示意当所有入口的硬编码目录。

## 四、变体设计与单次执行

| 轴 | 可选择的声明参数 | 用户用途 |
|---|---|---|
| 调色 | profile、LUT、intensity | 冷暖与风格表达 |
| 音乐 | 曲目 id/实际路径、配方、电平、原声策略 | 情绪与推进 |
| 转场 | hard、fade、xfade 的实际请求 | 调整节奏表达 |
| 封面 | 指定时刻、标题、字体、布局 | 平台入口图 |
| 文案 | 已给正文或本地模板 | 对应发布语气 |

按已选配方分别实际执行，不抽帧测两版本平均像素差、不测音频差异、不要求两个轴“足够不同”。清单里的 distinctness/divergence/samples 未测即 null/空数组，不以未测冒充通过。

音乐从明确的干净原声来源混入一次。禁止把带旧音乐的母版再作为变体底重复叠音乐；无音轨素材可为混流生成等时长静音 program，不能自动补台词。

## 五、可执行入口与参数边界

```bash
node bundles/ai-video/connectors/post-bridge/cli.mjs variants
node bundles/ai-video/connectors/post-bridge/cli.mjs plan --project project.json --shots shots.json
node bundles/ai-video/connectors/post-bridge/cli.mjs deliver --project project.json --shots shots.json --out-dir delivery
node bundles/ai-video/connectors/post-bridge/cli.mjs impact --project delivery/film-project.json --patch patch.json
```

- 字体、曲目与源素材必须是真实可读文件；显式无效分轨或曲目引用禁止回退默认轨。
- 所有输入只读；禁止覆盖源镜头、旧工程或旧版本目录。
- UHD 的目标画布仍必须实际产出并回读；不以 HD 预览代替，也不把未请求增强写成模型已执行。
- 每个请求变体与附件必须实际完成；真实编码、混音、文字、封面或落盘失败必须传播，不丢失败版本后声称完整。
- 平台与用户明确约束是实际输出契约；成功源的原 FPS、原分辨率或原声音品质不作后期二次否决。

## 六、SOP

1. **触发**：来源已成功渲染。读取并验证当前任务、源输入和文件字节。**回执**：shotGeneration=reused、实际镜号与 SHA-256。**失败**：供应商、来源或权限不符停止，不自动重提交。
2. **触发**：交付配方已声明。生成母版和请求的每个本地层。**回执**：逐层真实工具调用、参数、产物与血缘。**失败**：非零退出或缺文件立即停止出口，旧版本与源片保留。
3. **触发**：各层产物齐备。装入字幕、封面、工程和清单。**回执**：每个路径、字节数、哈希、实际画布、qualityReviewed=false。**失败**：缺件或当前哈希不符不能记为交付完成。
4. **触发**：返修或用户选版本。记录用户选择与影响层。**回执**：所选变体、版本与工程哈希。**失败**：过期工程或并发冲突停止，不覆盖新版本。

## 七、失败诊断（原因 → 处置）

| 症状 | 检测器 / 原因 | 处置 |
|---|---|---|
| 某变体缺失 | 工具非零、路径或曲目缺件 | 指名实际失败，停止完整交付；不静默降原声或省略 |
| 字幕有旁挂无软轨 | softmux 请求未执行或失败 | 补真实 softmux 处理；不能把计划清单当产物 |
| 曲目注册 id 可用但变体找不到 | id 未解析成真实路径 | 使用同一已解析文件与许可引用，禁止切另一首掩盖 |
| 母版被外部修改 | 工程 SHA-256 与当前文件不同 | 停止复用、核对来源，旧记录保留 |
| HD 被标成 UHD | 目标画布回读不符 | 按实际请求重编码该本地层，禁止伪造规格 |
| 字体或封面缺件 | 文件不存在、许可或处理错误 | 报具体缺件，禁止系统字体或空封面兜底 |
| 用户觉得两版本接近 | 用户明确意见 | 改声明配方后本地返修，默认交付不以差异评分拒收 |

## 八、证据口径与运营指标

| 指标 / 事实 | 口径 | 来源 |
|---|---|---|
| 请求出口完整 | 每个声明产物实际存在、非空、当前哈希一致 | manifest 与执行回执 |
| 镜头复用 | 已渲染来源保持，未触发新付费任务 | 原片哈希、taskId、阶段 invoked |
| 旁挂时间轴 | 写出 cue 与已定文字格式一致 | subtitle-manifest |
| 软轨 copy | 完整编码包哈希保持 | softmux 回执 |
| 默认品质复核 | false，所有未测品质值为 null | 各工位 report |
| 用户首选与返修率 | 仅真实用户选择事件汇总，不编目标达成 | delivery.variant.selected / revision |

本地媒体操作可声明本次未新增镜头 token；若明确配音、增强或其他引擎另有成本，必须按实际调用记录，不能无条件写整个系统“零成本”。

## 当前后期技术验收（2026-10-14）

成功源片复用与正式交付放行分别记录：来源、授权和当前字节成立后复用；当前母版、每个请求变体和附件必须通过完整解码、实际画布/帧率、字幕时间轴、真实输入/输出加工凭证和最终 SHA 检查。调用 `postread.quality` 重新检查当前包，不读取旧 `passed` 作为本次证据。艺术未审片保持 `qualityReviewed=false`；实际响度/真峰值默认 report 留测量，只有明确 block 音频合同按其目标阻断。不因技术失败自动付费生成、ASR/TTS 或外发。

连续返修保留累计文案与各版本工程；局部修改只改变点名变体，未点名文案文件按当前 SHA 原样复用。封面、字幕、弹幕和中文整理后的实际文件再次验收，失败保留原片和旧发布版本。
