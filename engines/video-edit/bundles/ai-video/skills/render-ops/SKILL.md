# 渲染提交与成功原片接受

## 两条路径

- **新生成路径**：仅缺失镜头或用户明确授权重生成的点名镜头，进入新的冻结请求、预算和 G8 提交。
- **成功原片路径**：供应商真实成功、任务/项目/镜号/输入/当前产物字节匹配时立即接受到正式后期；不重新打开旧镜的脚本、定妆照或品质评审。

身份、服装、动作、画质、名义时长、嘴型、台词和声音品质均不作成功原片默认后期闸。原片声音保留，默认不调用 ASR、TTS、LLM 或抽帧投票。组件升级和历史质量拒绝不能触发同一成功原片重新付费。

## 新任务参数与前置校验

| 项 | 必需事实 | 失败路径 |
|---|---|---|
| 脚本版本 | CMS 当前冻结版本与 parent_version | 版本/内容不符则不提交 |
| 定妆/材料绑定 | 本次新生成引用的 binding-manifest 与用途 | 缺授权或错误用途阻断 |
| 审批与预算 | 当前 G8/预算/支付授权 | 不通过不得花钱 |
| 租户与项目 | 任务属于本次作用域 | 不跨租户复用回执 |
| 提交参数 | 当前镜头卡的合法画幅、首帧、负面约束与计划参数 | 非法请求明确拒绝 |
| 任务幂等 | 已提交 task_id 与版本对应 | 未知/轮询中不得重复计费 |

这些只检查待新生成镜头。已成功旧镜的参考照过期、历史卡片格式、当前计划或导演组件变化，不重新要求其付费前置评审。

## SOP 与回执

1. 触发为新生成请求；固定项目/镜号/脚本版本/素材许可/预算与审批，回执记录冻结输入。失败不提交；不默改需求。
2. 提交一次并保存真实 task_id、请求版本与费用。手动单镜、批量和已授权自动化均遵循同一边界；没有提交回执不能宣称已生成。
3. 按实际 task_id 轮询并回填状态。仍处理、未知或超时时保留状态，禁止盲目再提交同一镜防重复计费。
4. 供应商 succeeded 后核对真实文件、项目/镜号、任务来源、输入/产物 SHA256；追加独立接受回执并进入正式后期，品质分 null。
5. 历史成功但旧品质拒绝的原片采用相同来源核验，原质量失败日志保持只读，接受以新增记录表示；新请求只处理未生成或明确点名的新镜。

## 来源与接受参数边界

1. 供应商 failed、来源 error/gateBlocked 或任务不符不能伪造 succeeded。
2. 当前源片字节必须与真实成功任务/冻结来源绑定；篡改、缺失或不可读明确失败。
3. 原输入与历史日志禁止原地覆盖；canonical 接受/后期副本不能改原始 raw 字节。
4. 后期组件 recipe 变化不能让已成功原片重新提交；真实缺件/来源失败也不能假装已接受。
5. 新生成授权、支付、租户与 G8 必须独立存在，成功素材接受不是扩大权限。

## 失败诊断（症状 → 原因 → 处置）

| 症状 | 检测器/原因 | 处置 |
|---|---|---|
| 提交被拒 | 当前新任务脚本/参数/素材绑定 | 修当前新请求，保留拒绝，不影响已成功旧镜 |
| 长时间无回填 | task_id 轮询实际状态 | 记录未知/超时，核对同一任务，不盲目重提 |
| 供应商失败 | 真实 failed 状态与错误码 | 保存失败；必要新请求需原授权/预算，不能按品质自动重试 |
| 成功文件缺失/损坏 | 实际文件/读取/加工 | 明确缺件或处理失败，不能写品质通过代替 |
| 项目/镜号/来源哈希不符 | 冻结任务和当前字节 | 来源失败，阻断冒用 |
| 已成功镜被旧身份/服装等拒绝 | 历史品质日志 | 来源核验后追加接受，不删旧失败、不重新付费 |
| 预算或支付不符 | 原 G8/支付/租户围栏 | 阻断新生成，不能绕闸 |

## 输出契约

新生成保存脚本版本、审批卡、task_id、费用与真实供应商结果；接受保存真实来源、当前原片 SHA256、新增接受记录、未评审声明和正式后期结果。关键数据无工具证据标未核实；历史失败与新接受可同时对账。
