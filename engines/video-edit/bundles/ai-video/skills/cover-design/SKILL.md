# 封面设计

## 请求组成与默认方法

封面由明确标题和主视觉组成；只有用户/请求明确要求人物层时才加入已指定人物来源。成功源镜默认接受，不能为封面寻找“更好”的人物、地标或造型而重新渲染。默认 `requestedCoverPlan` 在本地出稿，`source=requested`；模型设计、诊断和整图 rubric 保留为独立显式能力。

| 要素 | 实际输入 | 加工依据 |
|---|---|---|
| 主标题 | 非空标题，最多两行 | 请求文字，不自动改事实 |
| 主视觉 | 实际镜号与取帧秒数 | 源片当前 SHA256 |
| 人物层 | 可选指定镜号/取帧时间 | 不猜身份或新增人物 |
| 平台 | 请求平台及其画布参数 | 实际导出画布 |
| 字体/色板 | 账号指定或随包合法默认 | 白名单字体与 #RRGGBB |

## SOP（请求 → 本地合成 → 产物回执）

1. 触发为明确封面请求；核对 heroShotId、标题和非负有限取帧时间，来源与权限有效。不存在镜号、空标题或非法请求时失败，不自动换主视觉。
2. 读取平台和账号字体/色板；使用请求模板生成确定性设计稿。未知字体/非法颜色明确失败，禁止通过模型猜替代内容。
3. 从固定成功源片取指定帧，执行请求的底图处理、文字和可选人物层一次。原片只读，不为评价画面追加抽帧候选或生成新镜头。
4. 核对实际 PNG/JPEG 产物存在可读，记录 source/output SHA256、标题、镜号、时刻、字体与设计稿。`qualityReviewed=false`，不宣称整图审美通过。
5. 用户提出换字、换帧、人物位或色板时形成新的明确本地版本；历史失败和旧封面保留，品质分数不自动重做。

## 工艺与版式参考

| 项 | 建议值 | 说明 |
|---|---|---|
| 主标题字高 | 画幅高 6%–10% | 请求模板参考 |
| 副标题字高 | 主标题 42%–50% | 层级参考 |
| 描边 | 主标题 6%–8% | 复杂底图可明确请求底衬 |
| 抖音上标题带 | 6%–42% | 平台 UI 设计参考 |
| 抖音下带文字 | 52%–88% | 明确人物居中版式参考 |
| 底部留白 | 12% | 平台文案与进度条参考 |
| 参考取帧 | 0.8–1.6s | 用户可指定其他合法时间，不自动评分选帧 |

默认本地请求计划使用主字比 0.075、副字比 0.034，可选人物宽比 0.42。推荐短标题约 12 字、语义断行、不孤字，属于设计知识，不按默认画面测量拒绝合法请求。

## 字体与参数边界

1. 字体采用 `smiley-sans`、`source-han-heavy`、`zcool-qingke`、`noto-serif` 的实际随包文件；不能指定不存在路径。
2. 主标题非空且最多两行，hero/person 镜号必须实际存在，取帧时间必须有限且不小于 0。
3. 账号色板须为合法 #RRGGBB；来源、素材用途与字体许可必须覆盖当前用途。
4. 原片只读，输出为新文件；不存在的人物层不能伪造完成，也不能强制给无人片补人物。
5. 禁止默认 PSNR、标题带差异、人物层像素差或整图 LLM 品质投票；未测不是通过。

## 失败模式（症状 → 原因 → 处置）

| 症状 | 原因/首查 | 处置 |
|---|---|---|
| hero/person 镜号不存在 | 请求与实际源镜清单 | 返回 `cover_request_invalid`，不猜其他人物 |
| 标题为空/多于两行 | 原始请求文字 | 明确请求错误，不让模型改写事实 |
| 字体或色板非法 | 字体白名单、#RRGGBB | 指名非法参数，保留旧版本 |
| 取帧或合成失败 | 实际 FFmpeg/字体/路径日志 | 保存真实工具失败，不以原图冒充完整封面 |
| 原片/产物字节变化 | 来源 SHA256 与当前文件 | 来源失败，停止本次交付 |
| 用户说字小/压脸/调性不符 | 用户反馈与采用设计稿 | 明确改位置、字号、时刻后本地返修，不自动品质重跑 |

## 回执与知识边界

请求、设计稿 `source=requested`、实际镜号/时刻、source/output SHA256、画布、字体、色板、工具结果都写入原阶段回执。旧 `coverDeterministicChecks` 的品质分支与 LLM rubric 仅用于明确独立诊断，不是默认正式接受条件。
