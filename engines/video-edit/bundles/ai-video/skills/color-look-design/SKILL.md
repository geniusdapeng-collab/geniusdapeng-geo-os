# 题材与场景调色设计

## 适用场景与默认政策

用户要求一个调色方案或若干平台变体时，用内容意图选择明确的 profile、LUT 和强度。成功渲染镜头默认接受，原片和声音保持；没有请求调色时直接复用原片。人物、服装、动作、明暗、锐度和名义片长不构成后期拒收条件。

`colorwrite.best` 是兼容入口：当前按配方执行一次调色，`source`、`after`、`finalScore`、`improvement` 等品质值为 null，不再试渲多个候选或以分数决定是否产出。独立的 analyze、scope、compare 只在明确要求诊断时使用，不接入默认交付放行。

## 一、定调决策

1. 记录题材：产品、访谈、美食、科技、旅拍、夜景、美妆、亲子、汽车、房产、促销、纪录或品牌。
2. 记录主体与场景：人脸、商品、屏幕、空间；品牌指定色、LUT 与用户明确的强度优先。
3. 记录情绪：可信、温暖、诱人、精密、戏剧或克制；未知项按最接近的配方作合理选择并写明依据，不重新审核原镜头。
4. 记录平台与目标画布；参数建议用于计划，不抽样源片验证“是否足够好”。

## 二、配方检索与参数表

从仓库根运行真实 CLI；配方数量以本次返回为准。

```bash
node bundles/ai-video/connectors/color-bridge/cli.mjs recipes --list --json
node bundles/ai-video/connectors/color-bridge/cli.mjs recipes --genre 美食 --platform 小红书 --json
node bundles/ai-video/connectors/color-bridge/cli.mjs best --in clip.mp4 --out graded.mp4 --genre 美食 --json
node bundles/ai-video/connectors/color-bridge/cli.mjs grade --in clip.mp4 --out graded.mp4 --profile warm-film --intensity 0.6 --json
```

| 题材 | 情绪与配方方向 | 建议强度 | 设计意图 |
|---|---|---|---|
| 产品广告 | clean-bright | 0.7 | 干净、商品优先，遵守已给品牌色要求 |
| 人物访谈 | warm-film | 0.6 | 温暖、可信，避免擅改用户指定肤色风格 |
| 美食 | warm-film | 0.85 | 红黄暖调、保留餐具中性色的设计目标 |
| 科技 | cool-technical | 0.65 | 环境偏冷、信息清楚 |
| 户外旅拍 | teal-orange | 0.6 | 冷暖对照、保持场景叙事 |
| 夜景 | teal-orange | 0.75 | 保持夜景意图，不按白天亮度提亮 |
| 美妆 | clean-bright | 0.5 | 通透而克制，不擅自美白 |
| 亲子 | clean-bright | 0.6 | 轻暖、明亮 |
| 汽车 | cool-technical | 0.7 | 金属与精密感，品牌色要求优先 |
| 房产 | clean-bright | 0.55 | 空间清爽、减少过强风格 |
| 促销 | high-contrast-social | 0.8 | 有力度的视觉表达 |
| 纪录 | natural | 0.4 | 少风格、重内容 |
| 高端品牌 | moody-dark | 0.6 | 冷灰、克制 |

表中数值是历史配方选型建议；实际 profile、LUT 和参数取当前 recipes 回传，不把建议值变成成功素材的品质门。

## 三、情绪与平台适配

| 情绪 | 色温 | 对比与饱和 | 手法建议 |
|---|---|---|---|
| 可信专业 | 中性偏冷 | 中对比、中低饱和 | natural 或轻量 clean-bright |
| 温暖亲密 | 暖 | 中对比、中饱和 | warm-film，保留用户明确的白平衡 |
| 诱人热烈 | 暖 | 中高对比、较高饱和 | 配方驱动而非按抽帧分数自动加量 |
| 冷静精密 | 冷 | 中高对比、低饱和 | cool-technical |
| 戏剧故事 | 冷暖对照 | 高对比、中饱和 | teal-orange |
| 高级克制 | 冷灰 | 中对比、低饱和 | moody-dark |

小屏内容可选较明确的对比，官网与纪录可选较轻的强度。同一项目先定一套 look；平台变体仅按已请求的配方派生，不能为了“拉开差异”重复给已混音母版上音乐或重新评审原片。

## 四、参数边界

- intensity 使用大于 0 且不超过 1 的有效数值；需要不调色时直接复用原片，不把 0 当调色配方。LUT 必须是允许路径下实际存在的文件；非法值或缺 LUT 必须报错。
- 未请求 auto 或 denoise 时，不运行源帧亮度、噪声诊断。明确请求自动校正时，其诊断是该项操作的输入，不能变成所有素材的接受条件。
- 必须另存输出，禁止覆盖原镜头；视频与原音轨按实际执行回执对账。
- 禁止以裁切率、肤色色相、画面分数或两候选差值触发重渲、自动换配方或再次付费。

## 五、SOP 与回执

1. **触发**：用户或制作计划要求调色；读取当前来源文件与配方。**回执**：输入路径、SHA-256、配方 id、目标画布。**失败**：缺文件、作用域或来源不符时停止，不重生成。
2. **触发**：配方确定；执行一次 grade 或兼容 best。**回执**：profile/LUT、实际滤镜链、强度、工具退出码。**失败**：滤镜、编码器或 LUT 错误原样上报，不回退原片冒充已调色。
3. **触发**：执行结束；检查实际输出文件、画布、编码与声音保持。**回执**：输出 SHA-256、字节数、血缘、qualityReviewed=false。**失败**：缺产物或字节变化时停止交付，保留失败记录与原片。

## 六、失败模式（原因 → 处置）

| 症状 | 检测器 / 原因 | 处置 |
|---|---|---|
| 配方没有匹配 | recipes 返回无项 | 根据已知题材选择 natural 或用户明确参数，记录选型依据 |
| LUT 加载失败 | 文件缺失、路径越权或滤镜错误 | 指名文件并停止该请求；补齐合法 LUT 后再执行 |
| 请求输出不存在 | 工具非零或落盘失败 | 保留 stderr 与失败回执，禁止用原片充当新调色文件 |
| 原片被外部修改 | 当前字节与来源 SHA-256 不符 | 停止复用，核对真实来源；不因品质问题重提交 |
| 用户不喜欢本次 look | 明确用户反馈 | 走 color 层返修，记录新配方与新版本，镜头保持复用 |
