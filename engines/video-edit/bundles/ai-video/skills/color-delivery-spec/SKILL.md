# 调色交付规范

## 交付规格与工艺参数

| 项 | 当前口径 | 依据 |
|---|---|---|
| 色彩标签 | 输出 bt709 primaries/transfer/space | 实际 FFprobe 回读 |
| 编码 | 当前本地 H.264 / yuv420p 路径 | 采用的命令与产物规格 |
| 强度 | 大于 0、不超过 1；常用起点 0.5–0.85 | 明确请求参数 |
| 音频 | 保留原节目声音，按实际加工链记录编码 | 不做声音品质评审 |
| 命名 | `<项目>-<版本>-color.<ext>` | 新文件、版本只增 |
| HDR/ACES | 当前转换能力按明确支持路径 | 未支持的请求如实说明 |

成功渲染源镜直接进入正式后期。默认不检测身份、服装、动作、源画质、嘴型、台词和声音品质，也不因名义时长差自动退回。原片和历史品质失败只读；组件更新不重生成同一成功镜。

## 交付 SOP

1. 核对请求、源文件及来源 SHA256、租户/许可、输出新路径。触发为明确调色/派生请求，回执写实际输入；缺件或越权失败。
2. 确定 profile/LUT/强度、明确校正以及目标画布；执行一次本地变换。回执写滤镜链与版本；实际工具失败不得改写为成功。
3. 以同一已处理母版派生请求的平台版本；多风格变体则按已请求各套配方各执行一次。配方差异可说明，禁止抽像素复核差异或按品质分数重做。
4. 核对产物存在、可读、当前文件哈希、实际色彩标签与请求输出。未测 before/after/scope/残差/可见性为空，`qualityReviewed=false`、分数 null。
5. 用户提出偏冷、偏黄或强度变化时进入本地返修版本；未点名重新生成的镜头沿用原字节，保留历史回执。

## 必需证据与可选诊断

| 证据 | 默认是否必需 | 留痕内容 |
|---|---|---|
| 来源与作用域 | 是 | 项目、镜号、输入 SHA256、授权 |
| 请求与滤镜链 | 是 | profile/LUT/强度、实际校正 |
| 输出 | 是 | 路径、大小、实际时长、SHA256 |
| 实际色彩标签 | 是 | FFprobe 回读结果或真实错误 |
| 抽帧 before/after、scope | 否 | 仅显式诊断时采集 |
| 可见性、肤色、噪点、色带 | 否 | 未测为空；不作默认完成条件 |

## 参数边界与围栏

1. 原片只读（G-COL2）；禁止输入输出同路径，禁止覆盖已有来源或修改旧版本回执。
2. 请求的品牌配方、许可、作用域与配额按实际围栏保留；不得以“直接接受”绕过新请求授权。
3. G-COL3 的品质条件已停用（`when: false`）；真实加工、文件与哈希由连接器强制核对，不能以 `verify=false` 阻断正常后期或关闭技术检查。
4. profile、LUT 和数值合法性保留，未知参数不能静默替换；合法的弱 look 仍能交付。
5. 未测的质量分、残差、差异、缺陷结论必须为 null 或明确未评审，禁止把元数据校验包装成画面品质通过。

## 返工与失败模式

| 现象 | 原因/首查 | 处置 |
|---|---|---|
| 输出或哈希缺失 | 工具没有完成/文件变化 | 返回失败，保留原片和真实日志 |
| 色彩标签与实际请求不符 | 编码/元数据参数 | 明确加工失败，修请求或工具后重新发本地操作 |
| 用户觉得偏色 | 用户明确反馈与原采用校正 | 仅修改校正段，形成新版本 |
| 用户觉得风格不符 | 配方选择 | 用户明确选择新 profile/LUT，不自动试候选 |
| 强度太过或不足 | `intensity` 请求 | 仅调整 look 强度，保留原片 |
| 来源缺陷/柔焦/纯黑 | 旧素材或创作意图 | 默认继续请求后期；只在明确诊断中记录意见 |
| 文件损坏或权限不足 | 真实读取/工具错误 | 阻断实际失败；不得将它写成质量未达标后自动渲染 |

## 版本与回滚

每次请求写新产物并绑定来源 SHA256，回滚引用旧文件。用户反馈变成清楚的参数变更；source/current hash 变化需重新核对来源，不能继承旧接受。组件升级、历史不可修复标签和低画面差异均不重开同一成功镜头。

知识入口：`library/color-kb/_INDEX.md`，CGRADE-002 色彩空间、CGRADE-003 平台特性、CGRADE-008 事故归因；保留诊断知识，但正式交付仅以真实请求执行与来源/权限为依据。
