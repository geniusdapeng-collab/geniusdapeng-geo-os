## 2. 系统不变量与目标链路

目标链路：

```text
用户合同 -> 复用/生成源片 -> compose/color/subtitle/BGM
-> 封面设计/合成/机检 -> 完整视频烧封 -> manifest -> 质量门禁 -> 发布包
```

守住的关键不变量：

- 无真实回执不算完成；
- 显式请求不得静默降级；
- 源片、封面、完整视频必须绑定当前字节与哈希；
- 完整视频而不是旁路 PNG/临时目录才是交付物；
- 生产规则由平台规格、账号档案和作业合同驱动，不固化当前案例。

## 4. 修复与联动

1. 新增 `cover-delivery-policy` 作为封面时长、风格别名、文案候选和稳定路径的统一策略。
2. `edit:cover` 将烧封成品从暂存区提升到交付根，并在 manifest 更新每个变体的真实标题、
   封面哈希、完整视频哈希、时长和发布推荐。
3. `full-chain` 在多风格 `deliver` 后为每支变体生成默认 0.6s 静音封面完整视频；
   G-DLV1 增加完整视频硬检查。
4. PRD `productionRequirements` 增加可选 `coverIntroSeconds`，并允许持续字幕与封面共存。
5. 封面计划增加版面宽度硬校验；确定性兜底稿会先语义断行，再在允许字级内收敛。
6. 更新工作台指南、能力 README、岗位规范、pipeline/fastlane 默认参数与 bundle 资产摘要。
7. 本地新增 `ai-video-complete-delivery` 技能，包含通用作业合同、生产流程、交付契约和
   独立媒体校验脚本；脚本不包含车型、人物、平台专属文案或固定镜头时间。
8. **联动地雷追加修复**：质量门原先用“完整发布视频条数必须等于变体数”校验，会把同一变体
   同时交付烧字版和弹幕版误判为失败；现改为每支变体至少有一条稳定、带哈希的完整视频，
   允许多种发布形态。显式 `--burn-intro 0` 也不再被错误标记为 `completeVideo=true`。
   该联动缺口已用纯函数断言和真实 `edit:cover` CLI 门禁锁定，修复提交为
   `96a906ec0e5261d14f2b9911ab176e67230a1944`。
