# AI 视频细分环节人工搭桥兜底

适用范围：通用视频制作管线与营销视频制作管线。目标是避免同一个细分环节因模型输出漂移、重复出现同类格式错误而无限重试，同时保持下游数据合同、事实边界和最终交付披露。

## 触发条件

同一 `projectId + stageId + subtaskKey` 至少有 3 次正式执行失败，也就是首次失败后再完成 2 次重试，且：

- 每次失败都有可核对的 attempt、运行编码、错误摘要和证据；
- 本轮没有未知的付费供应商结果；
- 当前问题属于已定位的格式、结构、字段完整性或确定性组装缺陷；
- 正常入口仍可提供该环节的完整输入、目标 schema 和下游消费者。

未达到 3 次失败、外部结果未知、权利授权未决、审批未通过或问题根因尚未定位时，不得人工搭桥。

## 允许做什么

Codex 可以依据该环节当前正式 schema 和既有数据语义，生成一份实质完整、可被下一环节正常读取的产物。它是受审计的恢复产物，不是模型调用成功、供应商任务成功或真实外部回执。

人工搭桥必须：

1. 不覆盖、不改写已有失败 attempt、事件和原始响应。
2. 从当前已通过的 G1/G2/G3/G4 或对应上游合同读取事实，不使用记忆、常识或竞品推测补事实。
3. 对缺失且上游未授权的事实保留空值、显式缺口或停止投递，不编造占位事实。
4. 按目标 schema 完成必填字段、类型、枚举、长度、数量和交叉字段校验。
5. 将产物、输入、schema、校验命令及证据写到项目归档的独立 `manual-bridges/` 路径并计算 SHA-256。
6. 使用下游正常接口投递；通过下游门禁与审批后才算被接受，绕门禁直接宣传“完成”无效。
7. 在产物侧车和最终交付报告中显式标记 `manualBridge=true`，不得伪装成全自动生成。

## 禁止做什么

- 不得用手写 JSON、占位图、静帧或拼接文本冒充真实社交发布、付费供应商回执、成功视频任务或真实媒体文件。
- 不得跳过事实、权利、隐私、平台规范、审批、预算或技术/艺术验收门禁。
- 不得在外部请求结果未知时重发供应商请求；先查询原任务和原回执。
- 不得因采用兜底而删除失败历史、把 `degraded` 改成 `false`、或把人工内容标成模型生成。
- 不得把源片不存在、付费生成完全失败或关键人物/商品缺失的作业包装成合格成片。此时只能交付明确的局部产物或失败报告。

## 标准记录

每次人工搭桥使用 `pengmanager.video-manual-bridge/v1` 清单，字段和限制见 `video-manual-bridge.schema.json`。可用以下命令核验当前文件字节、证据和披露字段：

```bash
node scripts/validate-video-manual-bridge.mjs \
  --root <项目归档绝对目录> \
  --manifest <manual-bridges 清单绝对路径> \
  --json
```

清单必须绑定：

- 项目、管线、阶段和细分环节；
- 至少 3 个同一细分环节的失败 attempt；
- 输入、schema、输出和校验证据的路径及 SHA-256；
- schema/交叉字段校验器与退出码；
- 是否只使用上游事实、是否含编造事实、未解决事实和偏差；
- 付费调用、外发动作、不可逆动作计数；
- 下游交接状态；
- 最终交付披露文本。

## 最终交付披露

成片交付说明必须列出每个采用人工搭桥的环节：

- 阶段和细分环节；
- 正式失败次数及证据路径；
- 人工补齐的产物路径和 SHA-256；
- 使用的数据规范及校验回执；
- 数据是否失实、是否使用上游未授权事实、仍未解决的事实；
- 是否产生付费调用、外部发布或不可逆动作；
- 下游是否按正常门禁接受；
- 对成片质量和权利边界的剩余风险。

没有采用人工搭桥时，也必须在交付报告的同一栏目写明“未使用”。
