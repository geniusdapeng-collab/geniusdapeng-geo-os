# 鹏经理完整视频运行时

鹏经理主要通过 Codex 的 CLI 和 MCP 调用，根控制台保留自己的身份、内容状态和 GEO 数据。完整视频引擎来自仓库内的 `engines/video-edit`，默认 headless，只启动独立的本机 PostgreSQL、原生后端和工具进程。完整工作台源码一并保留，未来需要时可显式启用。源码固定版本和逐文件字节清单分别见 `upstreams/workloom-video-edit.pin.json`、`upstreams/workloom-video-edit.snapshot.json`。

## 安装与启动

要求 Node.js 24 或以上。内置引擎有自己的完整 workspace 和锁文件；安装、构建使用它的 `packageManager` 精确版本，根仓的包管理器版本不代替该版本。`PENGMANAGER_PNPM_BIN` 可以指定相应 pnpm 可执行文件或 JavaScript 入口，运行时会先核对版本。

固定 UI 包从生产者的[官方公开 release](https://github.com/geniusdapeng-collab/workloom-im/releases/tag/ui-v0.1.19)下载，无需额外发布凭据。下载器核对固定 release、制品身份、大小、SHA-256 和 SRI，再预热本实例自己的私有依赖 store，按原始锁文件离线安装。历史 canonical 锁身份和原包字节不变；临时下载传输不会改写包版本、锁文件或 CAFS 身份。发布凭据不传给 pnpm、构建、工具或视频后端；安装期间只在内存中处理原包，不写入或上传仓库。显式 legacy CNB 下载接口仅用于兼容和边界回归，不是当前默认安装路径。

首次安装使用包含 pgvector 的 PostgreSQL 17 工具目录，目录中应有 `bin`、`lib` 和 `share`。工具被复制到鹏经理私有数据目录；数据库数据不从其他项目导入。

```sh
node scripts/video-setup.mjs --postgres-root /absolute/postgresql-17-prefix --install
node scripts/video-doctor.mjs
node scripts/video-start.mjs
```

`--data-dir /absolute/private-directory` 可以选择新的私有数据目录。该目录必须在源码仓库以外，且只能由当前用户访问；安装不会接管现有的其他数据库端口。`video-setup` 默认安装本地媒体工具，模型及浏览器依赖通过固定版本配方获取，实际可用情况写入该私有目录的工具安装回执。

直接启动视频命令会保持前台监督，按 Ctrl-C 停止其自有后端、工具和数据库。CLI 和 MCP 管理同一运行时；同一数据目录的锁会拒绝第二个监督进程。默认 headless 模式不要求构建 Web、不占用 Web 端口，也不把工作台交互作为能力调用前置条件。

默认本机端口如下，可通过 `PENGMANAGER_VIDEO_*_PORT` 环境变量逐个修改，且各端口必须不同：

| 服务 | 默认端口 |
| --- | ---: |
| 视频 PostgreSQL | 16432 |
| 原生视频后端 | 18797 |
| 完整视频工作台（可选） | 14318 |
| Compositor | 19773 |
| 调色 / BGM / 字幕 / 后期 | 19774 / 19775 / 19776 / 19777 |
| 语音桥 / MLX 语音引擎 / CPU LoomMate | 19778 / 19779 / 19780 |

程序接口可用 `createVideoRuntime({serveWorkbench: true})`，或在启动进程前设置 `PENGMANAGER_VIDEO_WORKBENCH=1` 显式启用未来工作台。启用前用 `video-setup --build` 构建 Web；入口为 `http://127.0.0.1:14318/ai-video/assets`。后端和可选工作台均绑定 loopback。原生 API 会话通过本机专用启动密钥取得；网页使用同源会话、HttpOnly Cookie 和 CSRF 校验进入，启动密钥不会放进 HTML。

## 数据、凭据与装配

macOS 默认私有目录为 `~/Library/Application Support/PengManager/video-runtime`。其中包括数据库、工作档案、媒体、工具安装、日志和凭据状态。Linux 使用 XDG 数据目录，Windows 使用本机应用数据目录。不要把这个目录提交到 Git。

数据库实例与凭据绑定，现有实例缺少原凭据、实例身份变化或端口被其他服务占用时，运行时会拒绝启动。不会为已有数据库静默生成替代凭据。已有鹏经理 JSON/GEO 数据继续使用根控制台原有存储。

初始化只写入正式租户、主理人身份、原生行业包、岗位、围栏和技能元数据。它不导入上游演示任务、审批、渲染结果、经营指标或旧数据库。已有档案通过原生冲突处理保留，装配版本和策略变化会触发幂等升级。

完整装配显式启用两个内置模式：

- `WORKLOOM_PRESERVE_SHADOWED_ROLES=1` 保留 97 个原兼容岗位键，并把 4 个同名岗位各自保留为 `bundle--preset` 别名，共 101 个独立岗位。别名保留原岗位正文、工具、技能、风险和重试声明，来源可追溯。
- `WORKLOOM_DECLARED_SKILLS_REQUIRED=1` 要求岗位引用的技能有当前安装版本和非空正文，规划执行使用实际已安装技能内容；缺失或版本不符时拒绝继续。

原生初始化安装 108 个包内技能和 12 个官方技能，共 120 个。完整目录另列出 3 个可选 registry 技能，其代码随仓分发，依赖、签名和安装状态单独显示。目录中的 334 个工具声明与 80 项能力是可核验的源码目录信息，各工具的运行依赖与实际产出由相应回执说明。

## 模型设置与审批

模型供应商配置从当前进程环境取得。原生向导保存模型设置时会真实试调，但完整视频运行时把 `WORKLOOM_ENV_PERSIST_MODE` 固定为 `process-only`：配置仅在当前后端进程生效，不写 `.env`。重启后必须重新提供模型配置，且历史试调事件不能替代当前进程的成功试调证明。

原生“启用真实模式”仍检查当前经营主体、岗位、围栏、技能、装配与模型证明；已有 `dataMode=real` 字段本身不会通过该门槛。模型凭据不进入源码、浏览器 HTML 或完整日志；原生事件只保留原有脱敏掩码。

运行时固定 `WORKLOOM_RENDER_AUTO=0`，生成提交保留脚本审批、预算、资格签发、一次性消费与当前来源/字节校验。后台自动巡检、启动时线程自动恢复、档案自动恢复及云同步默认关闭。需要恢复已有任务时，通过原生任务/档案入口检查持久状态和未决供应商结果，再执行原生恢复流程。

## 媒体工具与授权状态

工具监督进程只启动和停止自己的进程组；不会复用或终止其他 Edit 安装的服务。安装成功与当前服务健康分别展示，过去的健康状态不代替当前探测。工具启动失败、端口冲突、模型文件缺失或哈希变化会显示明确原因。

Compositor 集成使用仓内固定的 headless kit、MIT 许可和来源记录，属于兼容的 headless 作图/渲染路径。它不表示本机已构建或安装不兼容宿主系统版本的官方桌面 App。

TalkCraft/Remotion 保留完整安装、卡片和非商业评估入口。商业执行要求真实存在的 `LICENSE-GRANT.md`，没有该授权时商业状态保持未就绪。原生视频生成、口播剪辑、语音和白板入口分别保留自己的依赖与授权门槛，不把一次依赖烟测表述为商业内容授权。

## 检查与升级

启动和安装前先核对内置源码清单及其 pin 摘要，再检查依赖和构建。清单包含完整固定上游文件、显式目标适配和目标新增文件，逐文件核对 SHA-256；这是 B 级字节证据，不表示逐行语义审计。

上游升级应重新生成逐文件清单与适配理由，保留鹏经理覆盖层，然后重新安装必要依赖、构建工作台、执行回归与独立运行验收。源码清单未封存、文件字节不符、依赖指向其他安装、必要的原生依赖构建缺失或私有目录权限不符时，诊断会显示失败原因；Web 构建只在显式启用工作台时要求。

仓库测试覆盖私有目录、凭据、锁、取消、进程失败、当前健康、同源会话、路径限制与快照篡改等边界。实际本机模型/媒体产出和源码不可读条件下的完整启停验收使用单独的脱敏回执；测试夹具的协议响应不作为真实供应商或真实经营证明。备份/恢复 UI 属于后续运营增强，当前私有数据库和原生档案持久化照常保留。
